Reverse-engineering the Jane Street 2026 ASIC puzzle

code the puzzle September 2026

You get a chip layout (a GDS file) with an unlabeled sea of standard cells, one input bit, one success output, and a hint image. The question is which input bitstream makes success go high. The answer, for the impatient, is (* TWO STARS *). Here is how I got there.

Short version

  1. GDS → KLayout LayoutToNetlist (metal → wires)
  2. Custom pin-attach (wires → standard-cell pins) → unlabeled netlist
  3. Simplify: drop filler cells, collapse buffers
  4. Replay example_inputs.vcd to verify the sim; notice the 121-clock frame
  5. Cluster cells by physical locality (MST), seeding the shaded “output generator” as its own cluster to ignore
  6. Probe / brute-force the small clusters: canned phrases fall out, and so does the contract for success
  7. SAT-solve the full netlist: which 121-bit input gives success = 1?
  8. Replay the one answer → (* TWO STARS *)

Long version

I'm not really a circuits person, and I knew very little about them going in. After the warm-up taught me a bit about the file types, it was clear that GDS wasn't useful to me directly: I'd need to extract a netlist before I could simulate anything with the suggested tools. I hoped this was already a solved problem, and it mostly was. KLayout's LayoutToNetlist groups the metal into wires. I wrote some pin-attach code on top of that to get the wires onto standard-cell pins, and finally had a netlist.

I was sort of hoping that after all of that, the next part would be the easy part. LMAO.

I reused the harness I'd built for the warm-up: sweep inputs through the circuit and graph the outputs every way I could think of, looking for a pattern. Primes, random samples, funny numbers. The hope was that the function would be simple enough to deduce from data, extrapolate a rule, and read off the secret code. Honestly, the only thing I learned at this stage (more an assumption I ran with) was that nothing comes out until the clock hits 121. Part of that came from checking my circuit against the recording they provided, example_inputs.vcd.

Then I went back to the hints. The shaded-region PNG worried me the more I thought about it. There was no reason to include it unless they wanted us to map sections of the GDS onto sections of the netlist and reverse-engineer from there.

So I clustered the circuit into pieces that would be easier to probe, on two assumptions. First: the shading was imprecise and they said we didn't need to touch that region, so there was probably some leeway. I didn't need perfect clusters. Second, just thinking about circuits: proximity is probably a signal. Cells that sit close together and wire directly into each other are probably doing one abstract thing. That didn't feel like a crazy assumption. One cluster came from the shaded region; the rest came from a minimum-spanning-tree clustering over physical position. That gave me a handful of components.

I simplified each piece on its own to get smaller circuits. One had few enough inputs to brute-force, and that produced canned phrases: EMPTY SKY, BIG BANG, TWO"NOT TOUCH. I had basically read their ROM.

The component driving success was also small. Exhausting its inputs told me which internal wires make the checker fire. But those wires aren't the input I; they're deep inside the chip. So I SAT-solved the full netlist: given 121 clock cycles (also a guess, but the evidence supported it), which input bitstream makes success = 1? One answer. Replayed it: (* TWO STARS *).

Then, like an idiot, I realized 121 is a grid, not a number length.

I spent some time after that just poking around and finding more things. I also finally noticed that layer 200 had Morse code the whole time. Missed it until after I'd solved.

A longer version with figures is coming. The code is in the repo.
